   - 이 문서의 0장, 0-2장, 1장, 4장, 5장. 2장과 3장은 구현에 반영한 결정과 조사 기록입니다.

   1. **설치와 실제 환경 확인**: 사용자 범위(`--scope user`)로 설치하고 데몬을 새 바이너리로 띄웁니다. 작은 프로젝트 하나로 `forget`, `project remove`, GUI 기록 탭을 확인합니다. 이번 세션은 격리 루트와 해시 임베더로만 확인했습니다.

5. 커밋과 push는 사용자 확인 후에만 합니다. 커밋 전에 `git diff --cached`로 개인정보와 회사 정보를 확인합니다.

## 0. 끝난 결함 수정: LanceDB 버전 누적 (SRS 0.15)

- 증상: 큰 프로젝트의 `vectors.lance`가 110GB(버전 69,608개)가 되어 디스크가 가득 찼습니다.
- 원인: 레코드마다 `delete`와 `merge_insert`로 커밋 2번을 했고, 정리를 하지 않았습니다. 버전마다 매니페스트가 모든 조각 목록을 담으므로 크기가 커밋 수의 제곱에 비례했습니다. 데이터 파일은 작았습니다(부록 D).
- 수정
  - 묶음마다 `VectorStore::replace` 한 번(삭제 1번, 추가 1번)으로 저장합니다(FR-STO-7). 재색인은 페이지 단위입니다.
  - `VectorStore::optimize`(compaction, 최신 버전만 남기는 prune)와 `pending_changes`가 있습니다(FR-STO-12).
  - 정리 시점: 수정 수가 `[index] optimize_every`(기본 20) 이상일 때, 그리고 임베딩 큐가 비었을 때
  - 정리는 같은 핸들의 잠금 안에서 합니다. 다른 핸들에서 prune하면 이전 버전을 든 핸들이 실패합니다.
- **기록 삭제(FR-DEL)를 구현할 때**: 벡터를 지우는 쪽도 지운 뒤 `indexer::optimize_if_due`를 불러 정리 규칙을 따르게 합니다. 여러 레코드를 지울 때는 `delete`를 반복하지 말고 `replace(refs, &[])` 한 번으로 지웁니다.
- 검증: 레코드 2만 개 → 버전 1개, 82.3MB(원시 벡터의 1.00배), 2.6초

### SRS 0.16에서 더한 것
- 요청 범위에 프로젝트 id(`Scope::Id`)를 더했습니다. GUI가 선택한 프로젝트를 지정할 때 씁니다.
- `search`에 `structured` 필드를 더했습니다. 참이면 결과 목록(프로젝트 id, prompt_id 포함)을 돌려줍니다.
- 이전 데몬은 `Scope::Id`를 받으면 해석 오류를 냅니다. 그러나 `structured: true`는 모르는 필드로 보고 무시한 채 텍스트를 돌려줍니다. 그래서 다시 설치할 때는 데몬도 반드시 새 바이너리로 띄웁니다.

### 구조
- 삭제: `RecordStore::forget(target, dry_run)`가 한 트랜잭션 안에서 대상을 정하고 지웁니다. `dry_run`이면 되돌립니다. 그래서 미리 보기와 실제 삭제는 같은 대상 선정 규칙을 씁니다(FR-DEL-6).
- 데몬의 삭제 순서: 미리 보기로 작업 목록을 얻음 → 메모리 큐에서 뺌 → `embed_lock`을 잡음 → 실제 삭제 → `replace(refs, &[])` 한 번 → `optimize_if_due`
- 임베딩 스레드는 잠금을 얻은 뒤 프로젝트가 목록 DB에 있는지 확인합니다. 지운 프로젝트의 디렉터리를 다시 만들지 않게 하기 위해서입니다.
- 주입: `build_injection`은 `plan_injection`을 부르는 얇은 함수입니다. 실제 주입과 미리 보기가 같은 함수를 씁니다.
- 턴 상세: `turn_views`가 구조체를 돌려주고, `render_turn`(`hippo show`의 출력)도 이 구조체로 출력합니다.
- GUI 상태 로직은 `src/gui/state.rs`의 `RecordsView`와 `DeleteTarget`에 있고, `tests/gui_state_test.rs`에서 시험합니다.

### 검증
- 테스트 411개 통과, 무시 2개, clippy 경고 0, fmt 통과
- 일부러 결함을 넣어 테스트가 잡는지 확인했습니다.
  - 결과 FTS의 `indexed = 1` 조건을 빼면 FTS 무결성 검사가 실패합니다.
  - `forget`에서 임베딩 잠금을 빼면 처리 중 묶음의 경합 테스트가 실패합니다.
- 격리 루트(`/tmp`, 픽스처, 해시 임베더)에서 화면을 확인했습니다.
  - 세션 → 턴 → 상세
  - 필터, 페이지 넘김(세션 55개, 2쪽)
  - 주입 미리 보기
  - 세션 삭제와 프로젝트 삭제 확인 창, 삭제 뒤 목록 다시 불러오기
  - 검색 탭의 `기록에서 열기`
- 실제 설치 환경(Ollama, LanceDB, 큰 프로젝트)에서는 확인하지 않았습니다. 착수 블록 3-1에서 합니다.

## 3. 확인한 구현 사항 (구현 전 조사 결과. 0.16에 반영함)

### 삭제할 때 함께 정리할 곳
- 원본 저장소(`src/store.rs`의 `SCHEMA`)
  - `iterations`와 `iterations_fts`
  - `iteration_results`
  - `results`와 `results_fts`. 다른 곳에서 참조하지 않을 때만 지웁니다
  - `bg_tasks`, `bg_completions`
  - `embed_jobs`
  - `sessions`(세션의 수집 위치. 세션 삭제일 때만)
- 목록 DB(`src/registry.rs`): `projects`, `project_roots`, `session_projects`
- 벡터 저장소: `VectorStore::delete(kind, ref_id)`가 그 레코드의 모든 청크를 지웁니다
- 데몬 메모리: `EmbedQueue::remove(project, jobs)`, `EmbedQueue::remove_project(project)`, 열어 둔 저장소 핸들(`OpenProjects::remove`)

### FTS 삭제 주의 (중요)
- 두 FTS 테이블은 외부 내용(`content='iterations'`, `content='results'`) 방식입니다. 행을 지울 때 `INSERT INTO <fts>(<fts>, rowid, <열>) VALUES('delete', rowid, <원래 텍스트>)`로 **원래 텍스트와 함께** 지워야 합니다.
- **색인에 없는 행에 delete 명령을 보내면 색인이 깨집니다.**
  - `iterations`는 모든 행에 FTS 행이 있습니다(`insert_iteration`, `merge_attached`).
  - `results`는 `indexed = 1`인 행에만 FTS 행이 있습니다(`insert_result`). `indexed = 0`(hippo 호출 결과)은 FTS delete를 보내지 않습니다.

### 임베딩과의 경합
- 임베딩 스레드는 묶음 하나를 처리하는 동안 `shared.embed_lock`을 잡습니다(`embed_batch`). 재색인도 같은 잠금을 씁니다.
- `index_one`은 원본 레코드가 없으면 벡터 없이 넘어갑니다(`load_source`가 `None`).
- 그래서 삭제 순서는 다음과 같습니다(FR-DEL-6).
  1. 메모리 큐에서 대상 작업을 뺍니다.
  2. `embed_lock`을 잡습니다. 처리 중인 묶음이 끝날 때까지 기다리게 됩니다.
  3. 원본 저장소와 벡터를 지웁니다.
- 렌더러처럼 긴 결과가 많으면 묶음 하나가 수십 초 걸릴 수 있습니다. 이때 삭제 요청도 그만큼 기다립니다.

### 데몬 구조
- 쓰기 작업은 `WriteJob`(일반: `Ingest`, `ImportPrepare` / bulk: `ImportSession`)을 `spawn_writer`가 처리합니다. 삭제 작업은 일반 단계에 넣습니다.
- 요청 분기는 `handle_request`에 있습니다. 쓰기 작업은 `send_write`로 보냅니다.
- 프로토콜(`src/protocol.rs`)
  - `Request`는 `#[serde(tag = "type", rename_all = "snake_case")]`입니다.
  - 새 필드는 `#[serde(default)]`로 넣습니다.
  - **이전 데몬과 새 클라이언트를 섞지 않습니다.** 이전 데몬은 모르는 필드를 조용히 무시합니다. 예를 들어 `dry_run: true`를 무시하고 실제로 지울 수 있습니다. 새 요청 종류는 이전 데몬에서 역직렬화 오류가 나므로 상대적으로 안전합니다.
- `show`의 프로젝트 탐색 순서(`fn show`)를 `forget`에 그대로 씁니다(IF-CLI-12).
- 턴 렌더링은 `search::render_turn`과 `render_iteration`에 있습니다. GUI 턴 상세는 반복별 구조 데이터가 필요하므로, 같은 내용을 구조체로 돌려주는 함수를 새로 둡니다.
- 주입 미리 보기는 `search::build_injection`의 후보 선택 과정을 판정 목록으로 돌려주도록 나눕니다. 실제 `inject`와 미리 보기가 **같은 함수**를 써야 FR-GUI-16의 검증("실제 `inject`와 같은 턴")이 의미가 있습니다.

### GUI (egui/eframe 0.37)
- 탭 구성은 `src/gui/app.rs`, 설정 설명문은 `src/gui/text.rs`, 공용 위젯은 `src/gui/widgets.rs`에 있습니다.
- 화면과 분리한 상태 로직은 `tests/gui_state_test.rs`에서 시험합니다. 기록 탭의 페이지, 선택, 삭제 후 다시 불러오기도 같은 방식으로 시험합니다.
- 0.37의 API 함정과 화면 확인 방법(accesskit, 창만 캡처)은 `docs/handoff-laya.md` 4장에 있습니다.

## 4. 값을 치르고 배운 것 (이번 세션)

### 측정
- 평가는 실제 데이터를 격리 루트(`--root <디렉터리>`)로 가져와서 합니다. hook 설치는 필요 없습니다.
- 실제 hook 경로 측정: `echo '<JSON>' | hippo --root <루트> hook user-prompt-submit`. 현재 세션을 빼려면 `session_id`에 그 세션 id를 넣습니다.
- 평가셋의 오주입 질문에 실제 과거 프롬프트를 쓰면, 그 프롬프트가 들어 있던 턴 자신을 후보에서 빼야 합니다. 그러지 않으면 유사도 1.0으로 맞습니다.
- 평가셋과 실제 대화는 저장소에 넣지 않습니다. 이번 평가 파일은 사용자 요청으로 모두 지웠습니다.

### 장비와 모델
- **모델을 여러 개 동시에 올리지 않습니다.** 32GB 장비에서 메모리가 가득 차 멈출 뻔했습니다. 한 번에 하나만 올리고, 끝나면 내립니다.
- 오래 걸리는 시험은 먼저 축소해서 돌리고, 중간 결과를 파일에 저장합니다.
- Homebrew llama.cpp는 kev 시험 때문에 0.8.0으로 올라가 있습니다.

### Claude Code
- Claude Code는 기본 30일이 지난 transcript를 지웁니다(`cleanupPeriodDays`). 그래서 9월 이전 세션은 가져올 수 없었습니다. 사용자는 이 설정을 늘리지 않기로 했습니다.
- `~/.claude/history.jsonl`에는 입력한 프롬프트만 남습니다(응답 없음). 가져오는 기능은 만들지 않았습니다.

### 사용자와 일하는 방법
- 사용자는 선택지 대신 자기 말로 답하는 경우가 많습니다. 해석이 둘이면 다시 확인합니다. 예: "보기 창 안에서 바로 쿼리"는 검색과 주입 미리 보기 둘 다였습니다.
- 진행이 길어지면 지금 얼마나 됐는지 묻습니다. 남은 양과 예상 시간을 숫자로 답합니다.
- 자동 주입은 작업 지시형 프롬프트("남은 기록 가져와", "새 세션에서 하자")에 관련 없는 기억을 넣는 경우가 여전히 있습니다. 주입된 기억이 질문과 맞지 않으면 무시합니다.

### 시험 잔여물과 그 원인 (0.16 세션)
- `cargo test`를 돌릴 때마다 `/tmp/.tmp*/root/projects/<id>/records.sqlite`와 `$TMPDIR/.tmp*`가 쌓였습니다. 이 세션에서 `/tmp` 144개, `$TMPDIR` 281개를 지웠습니다.
- 원인은 세 가지였고, 모두 고쳤습니다.
  1. **재색인 스레드의 순서(실제 결함)**: 재색인 스레드가 `reindexing` 플래그를 내린 뒤에 프로젝트마다 원본 저장소를 다시 열었습니다. 그 틈에 `project remove`가 들어오면, 지운 프로젝트의 `records.sqlite`가 다시 생깁니다. 이제는 다시 연 뒤에 상태와 플래그를 바꿉니다.
  2. `tests/lance_test.rs`의 계약 테스트가 `tempdir().keep()`으로 디렉터리를 남겼습니다.
  3. 테스트 두 개(`shutdown_is_rejected_during_reindex`, `preview_is_allowed_during_reindex`)가 재색인 중에 끝났습니다. 재색인 스레드는 `shutdown`이 기다리지 않으므로, 임시 디렉터리를 지운 뒤에도 돌았습니다. 이제는 재색인이 끝나기를 기다립니다.
- 새는 테스트 찾는 방법: 테스트 하나만 돌리면 프로세스가 바로 끝나 남은 스레드도 함께 사라집니다. 그래서 이름순으로 맨 뒤에 도는 느린 테스트(`zero_idle_timeout_never_exits`)와 짝지어 `--test-threads=1`로 하나씩 돌리고, 전후의 `.tmp*` 개수를 비교합니다.

### GUI 화면 확인 (0.16 세션에서 찾은 것)
- 좌표 클릭(`System Events` `click at`)은 창이 앞에 있을 때만 전달됩니다. 앞으로 가져온 뒤 첫 클릭은 창 활성화에만 쓰일 때가 있습니다.
- 접근성 API가 더 확실합니다.
  - 목록 항목(`selectable_label`)은 `checkbox`, 버튼은 `button "<이름>"`입니다(`UI element 2 of group 1`).
  - 확인 창의 버튼은 `UI element 3 of group 1`에 있습니다.
  - 입력란은 `keystroke`가 들어가지 않습니다. `set value of text field n`으로 넣습니다.
- 창이 뒤에 있으면 캡처가 빈 화면으로 나옵니다. 앞으로 가져온 뒤 찍습니다.
- GUI가 자동으로 띄운 데몬은 GUI를 닫아도 남습니다. 확인을 마치면 `pgrep -fl hippo`로 찾아 내립니다.

## 5. 아직 고치지 않은 것

  - `--test-threads=1`이면 실패하지 않습니다.
  - 0.16 수정 전에도 비슷한 빈도였습니다(수정 전 10번 중 2번, 수정 후 10번 중 1번).
  - 메모리 벡터 저장소만 쓰는 테스트에서도 나므로 LanceDB와는 관계가 없습니다.

- 80자로 자른 세션·턴 프롬프트에는 잘렸다는 표시가 없습니다. SRS FR-GUI-13의 문구를 그대로 따른 것입니다.

- `docs/handoff-laya.md`는 끝난 과제의 문서입니다. 지울지, 결론을 덧붙일지 사용자에게 묻지 않았습니다.

## 6. 변하지 않는 규약

`docs/handoff-laya.md` 6장과 같습니다. 핵심만 다시 적습니다.
- 인터뷰 → SRS(IEEE 29148) → 실패하는 테스트 → 구현 → 전체 테스트 순서. SRS와 코드가 다르면 SRS부터 고칩니다.
- 검증: `cargo test --no-fail-fast`, `cargo clippy --all-targets`(경고 0), `cargo fmt --check`. 실패 수는 `grep -c "\.\.\. FAILED"`로 셉니다.
- 심볼 탐색과 수정은 LSP → Serena → grep 순서입니다.
- 커밋과 push는 사용자 확인 후에만 합니다. 커밋 메시지에 AI 서명을 넣지 않습니다.
- 저장소는 공개 GitHub입니다. 개인 경로, 회사 정보, 이메일, 실제 대화를 파일과 커밋에 넣지 않습니다. 커밋 전에 `git diff --cached`로 확인합니다.
- `~/.claude` 설정은 사용자가 요청할 때 `hippo install`/`uninstall`로만 바꿉니다.
- 한국어 문서는 자연스러운 한국어로 쓰고, README는 영어판과 한국어판을 함께 고칩니다.
