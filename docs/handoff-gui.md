### 사용자가 정한 것 (모두 구현함)
1. **주입 단위는 턴입니다.** 검색에 걸린 반복의 턴(`prompt_id`, 같은 세션)을 가져와, 반복 순서대로 `[input]`, `[response]`, `[question]`/`[answer]`를 넣습니다. 도구 호출과 결과는 넣지 않습니다.
2. **자르지 않습니다.** 사용자가 "줄이는 건 안 된다. 차라리 내용을 바꿔야 한다"고 했습니다. 전체 한도(`total_chars`, 기본 12,000자)를 넘는 턴은 통째로 빼고 다음 후보 턴을 봅니다. 긴 입력도 그대로 넣습니다.
3. **시간순 정렬**: 블록은 턴 시각 오름차순입니다. 각 블록에 `ts`를 표시해 에이전트가 흐름을 판단하게 합니다. 최근 것에 가산점을 주는 방식은 쓰지 않습니다.
4. **노이즈**: API 오류 안내문(`isApiErrorMessage == true`)은 응답으로 저장하지 않습니다. `<task-notification>` 프롬프트에는 주입하지 않습니다.
5. **청크**: 1,000자, 이웃 청크와 200자 겹침(800자 간격). 임베딩 요청은 청크 하나에 하나씩 보냅니다. 자동 주입이 처리 중이면 임베딩 스레드가 다음 청크 요청을 미룹니다. bulk(import) 작업을 처리하는 중에 실시간 작업이 들어오면 작업 1건 뒤에 넘어갑니다.
6. **콜드 시작**: hook이 데몬을 띄워야 하거나 모델이 메모리에 없으면(Ollama `GET /api/ps`로 확인) 콜드 예산 `cold_budget_ms`(기본 2,500ms)를 씁니다. hook 제한 시간은 5초가 되었습니다.
7. **다음 순서**: GUI → Laya 재순위.

## 3. GUI 과제

### 사용자 요청 원문 (11/02 22:23)
> 사용자 옵션 및 설정을 gui 로 만들고 싶은데 가능할까?
> rust 에서 가장 가벼운 gui 라이브러리를 이용하고 cli 로 호출 시 해당 gui 가 보이게 하는걸로 할 수 있나?
> 여기서 옵션(임계값이라거나 등등등)을 변경할 수 있고, 3번의 미리보기, 혹인 import 시 어떤 세션을 추가할 지 선택하는 등의 내용, readme,라이센스 등 설명 보기 같은 기능을 넣으면 좋을 것 같은데.
> …
> gui 완성되면 claude 에 적용 및 적용 해제도 gui 내에서 가능하도록.
> 가능하면 모든 명령어를 gui 에서 사용하고 그 상태나 진행상황등을 볼 수 있도록 하면 좋을 것 같아.

"3번의 미리보기"는 직전 답변의 3번 항목인 **import 미리 보기**입니다. 실행 전에 어떤 세션이 후보인지 보여 주고, 과거 경로 목록을 보여 주는 기능입니다. 지금 CLI에는 `--dry-run`이 없습니다.

### 요구 기능 정리
1. `hippo gui`(이름은 결정 대상)로 창을 띄웁니다.
2. 설정 보기와 변경: `~/.hippo/config.toml`의 모든 항목(임계값, 예산, 청크, 언어 등)
3. import 미리 보기와 세션 선택
4. Claude 적용과 해제(`install`/`uninstall`, user/project 범위)
5. 모든 명령 실행과 상태·진행 상황 보기: `status`, `search`, `show`, `reindex`, `project list`, `import` 진행률
6. README, 라이선스 보기

### 이미 있는 재료
- 데몬 프로토콜(`src/protocol.rs`, Unix 소켓에 JSON 한 줄): `Status`, `Search`, `Show`, `Reindex`, `ProjectList`, `ImportPrepare`(후보 세션 목록 `ImportPlan.sessions`를 돌려줌), `ImportSession`(세션 하나 가져오기). GUI는 CLI와 같은 클라이언트(`hippo::client::request`)를 쓰면 됩니다.
- import는 이미 "준비 → 세션마다 가져오기"의 두 단계입니다. 세션 선택은 `ImportPrepare`가 돌려준 목록에서 고른 세션만 `ImportSession`으로 보내는 방식으로 만들 수 있습니다. 확인이 필요합니다.
- `StatusInfo`: 프로젝트별 반복·결과·임베딩 대기·벡터 수, 처리 속도와 남은 시간, 재색인 상태
- 설치: `src/install.rs`, `src/setup.rs`. diff 출력, `--dry-run`, 백업, 심볼릭 링크 거부가 이미 있습니다.
- 출력 언어: `[ui] language`(`en`/`ko`). 데몬은 요청마다 다시 읽습니다. Claude가 읽는 텍스트는 영어로 고정입니다(FR-UI-2).

### 결정할 것 (사용자와 하나씩, 의존 순서)
1. **GUI 방식과 SRS 2.6의 "웹 UI" 비목표**: 네이티브 GUI 라이브러리(예: egui/eframe, iced, slint)를 쓸지 정합니다. 웹뷰 기반(Tauri 등)은 비목표 "웹 UI"와 부딪칠 수 있습니다. 사용자는 "rust에서 가장 가벼운 gui 라이브러리"를 원했습니다. 후보별 바이너리 크기 증가와 빌드 시간을 실측해서 제시하는 것을 권합니다.
2. **바이너리 구성**: hook은 이벤트마다 실행되므로, GUI 라이브러리 때문에 hook 바이너리가 무거워지거나 시작이 느려지면 안 됩니다. 이번 세션에서 hook 시작 시간이 주입 예산에 직접 들어간다는 것을 확인했습니다. 후보는 (a) 같은 바이너리에 cargo feature로 넣기, (b) 별도 바이너리(`hippo-gui`)를 workspace로 두고 `hippo gui`가 그것을 실행하기, (c) 같은 바이너리에 항상 포함하기입니다. (b)를 권합니다. 결정 전에 (c)의 hook 시작 시간 변화를 실측하면 근거가 됩니다.
3. **설정 편집**: `config.toml`은 `deny_unknown_fields`이고, 값 검증이 `Config::parse`에 있습니다(로컬 URL, 겹침 < 청크 한도, 콜드 예산 ≥ 예산). GUI는 저장 전에 같은 검증을 거쳐야 합니다. 사용자가 손으로 쓴 주석을 보존할지(`toml_edit` 등) 정합니다. 데몬이 시작 때만 읽는 값과 요청마다 다시 읽는 값(언어)이 다르므로, 데몬 재시작 안내가 필요합니다.
4. **import 세션 선택**: 지금 `hippo import`는 후보 전체를 가져옵니다. GUI에서 고른 세션만 가져오게 하려면 프로토콜이나 CLI(예: `--dry-run`, 세션 지정)를 바꿔야 할 수 있습니다. 미리 보기에 무엇을 보여 줄지(세션 id, 시작 경로, 날짜, 크기, 첫 프롬프트) 정합니다.
5. **진행 상황 표시**: 데몬에 푸시 채널이 없습니다. `Status` 폴링 간격과, import·reindex 진행률을 어떻게 보일지 정합니다.
6. **범위와 순서**: 6가지 기능 중 1차로 만들 것을 정합니다.

## 4. 값을 치르고 배운 것 (이번 세션)

### 성능 실측 (이 장비, `qwen3-embedding:0.6b`)
- 청크 하나 임베딩: 500자 0.07s, 2,000자 0.23s, 8,000자 1.15s.
- Ollama는 `OLLAMA_NUM_PARALLEL:1`(단일 슬롯)로 동작합니다. 큰 요청 하나가 처리되는 동안 다른 요청은 모두 기다립니다. 슬롯을 늘려도 GPU 연산을 나눠 쓰므로 해결되지 않습니다. 서비스로 떠 있는 Ollama는 hippo가 설정할 수도 없습니다.
- 모델을 다시 올리는 데 약 0.75s 걸립니다. 데몬 유휴 종료와 모델 `keep_alive`가 둘 다 30분이므로, 30분 넘게 쉬면 첫 프롬프트는 콜드 상태입니다.
- 재설치 직후 **새 바이너리의 첫 실행**은 약 2.2s 걸렸습니다(244MB 실행 파일, macOS 첫 실행 검사로 추정, 미확인). 바이너리가 커지면 이 값도 커질 수 있습니다. GUI 바이너리 구성 결정에 참고합니다.
- 턴 길이(턴 137개): 모든 응답 텍스트 합은 중앙값 1,024자, 최대 4,555자입니다. 입력은 중앙값 137자이지만 상위 10%는 33,942자 이상, 최대 170,948자입니다(붙여 넣은 문서, diff가 든 리뷰 요청). 턴의 입력은 항상 첫 반복에만 1개 있습니다. 완료 알림과 서브에이전트 메시지도 새 턴으로 시작합니다.

### Claude Code 동작
- API 오류 안내문은 assistant 줄로 기록되고 `isApiErrorMessage: true`, `message.model: "<synthetic>"`를 가집니다.
- 백그라운드 작업 완료 알림(`<task-notification>`)에도 `UserPromptSubmit` hook이 실행됩니다.
- 이 세션 안에서 데몬을 `pkill`해도, 다음 도구 호출 뒤의 `PostToolBatch` 수집 hook이 데몬을 바로 다시 띄웁니다. 콜드 상태를 재려면 데몬 종료, `ollama stop <모델>`, 측정을 **한 명령 안에서** 연달아 실행해야 합니다.
- 자동 주입 측정은 실제 hook과 같은 경로로 할 수 있습니다: `echo '<JSON>' | ~/.hippo/bin/hippo hook user-prompt-submit`. JSON에는 `session_id`(현재 세션과 다른 값), `transcript_path`, `cwd`, `prompt`, `hook_event_name`을 넣습니다.
- `hippo install`은 기존 설정 파일을 바꿀 때 `settings.local.json.hippo-backup-<시각>` 백업을 남깁니다.

### 개발 중 겪은 함정
- `cargo test`는 첫 번째로 실패한 테스트 바이너리에서 멈춥니다. 전체 결과를 보려면 `--no-fail-fast`를 씁니다.
- Serena `replace_symbol_body`가 함수 위의 doc 주석(`///`)을 지운 적이 있습니다. 교체 뒤 `git diff`로 확인합니다.
- 청크 기본값을 바꾸자 벡터 수를 세는 daemon 테스트 4개가 깨졌습니다. 그 테스트 설정은 이제 `[chunking] max_tokens = 8000`으로 고정되어 있습니다(`tests/daemon_test.rs`의 `config()`).
- `memory` 벡터 백엔드는 데몬을 다시 띄우면 비어 있습니다. 재시작을 다루는 테스트는 같은 `Arc<MemoryVectorStore>`를 두 실행에 넘깁니다(`indexed_then_stopped`).
- `Request`는 `#[serde(tag = "type", rename_all = "snake_case")]`입니다. JSON은 `{"type":"inject",…}` 모양입니다. 새 필드는 `#[serde(default)]`로 넣어 이전 클라이언트와 호환시킵니다.

### 사용자와 일하는 방법
- 사용자는 선택지를 그대로 고르기보다 자기 말로 답하는 경우가 많습니다(예: "청크는 1000자로 1청크, 겹치는 건 앞뒤로 200자"). 답의 문장을 그대로 읽고, 해석이 둘이면 가정을 밝힙니다.
- 사용자가 질문으로 되물으면(예: "응답이 tool result를 말해?", "입력은 최초 1번뿐 아니야?") 데이터로 확인해서 답한 뒤 같은 결정을 다시 묻습니다.
- 다른 세션의 분석을 확인해 달라는 요청이 옵니다. transcript는 `~/.claude/projects/<slug>/<session id>.jsonl`에 있고, 로그(`~/.hippo/logs/hippo.log`, `ollama.log`)와 시각을 맞춰 봅니다.

## 5. 아직 고치지 않은 것

- **Laya 재순위(GUI 다음 과제)**: `NandhaKishorM/laya`. 비자기회귀 판단 모델이고, choice/score/noul 질문에 확률을 돌려줍니다. TypeSafe Jev와 같은 `POST /v1/systemone` 프로토콜을 씁니다. 조사한 사실은 다음과 같습니다.
  - 체크포인트는 `laya`(421M, 영어)와 `laya-multilingual`(322M, 100개 이상 언어)입니다. 한국어 정확도(MASSIVE intent, 저자 측정)는 laya 0.110, multilingual 0.470입니다. RAG 관련성 판단은 0.625/0.657입니다. 저자 측정치이고 독립 검증은 없습니다.
  - 실행에는 Python 3.10+, PyTorch, transformers가 필요합니다. `pip install "laya[serve]"`로 `laya-serve`(기본 0.0.0.0:8000)를 띄웁니다. GGUF/Ollama 배포는 없습니다. ONNX(`laya[onnx]`)는 있습니다. 라이선스는 Apache-2.0입니다.
  - 지연(저자 측정): M1 Pro 1행 58ms, M5 Pro 8행 136ms. CPU 4코어 1질문 193~580ms.
  - 주의: 기본 바인딩이 `0.0.0.0`이고 `LAYA_API_KEY`가 없으면 인증이 없습니다. 쓴다면 `127.0.0.1`로 묶어야 합니다. 로컬 모델이라도 새 AI 도구이므로 사내 정보보호팀 승인이 필요한지 확인해야 합니다.
  - 권장 순서: 과거 질문과 정답 턴을 짝지은 **평가셋**(10~20개)을 먼저 만들고, 지금 턴 단위 주입의 정답 포함률(recall@3)을 잰 뒤 재순위가 필요한지 판단합니다. 재순위 요청이 임베딩과 같은 장비를 쓰면 주입 예산 문제가 다시 생길 수 있습니다.
- **OPEN-5 임계값**: 0.40은 임시값입니다. 메타 질문("방금 주입됐어?")에도 관련성이 낮은 기억이 들어옵니다. 평가셋으로 함께 조정합니다.
- **재색인 중의 주입 우선순위**: 재색인은 별도 스레드라 주입 게이트를 따르지 않습니다(FR-DMN-6 (a)의 범위 밖). 재색인 중에는 주입이 청크 하나(약 0.1초)를 기다릴 수 있습니다.
- **데몬이 응답하지 않을 때의 지연**: hook 클라이언트가 콜드 예산(2.5초)까지 기다리도록 바뀌었습니다. 정상일 때는 영향이 없습니다.
- **untracked 파일**: `CLAUDE.local.md`(설치가 넣은 안내 블록)와 `.claude/settings.local.json.hippo-backup-*`(설치 백업)가 git에서 무시되지 않습니다. `.claude/settings.local.json`은 전역 git ignore로 무시됩니다. `.gitignore`는 사용자 결정 없이 바꾸지 않았습니다.

- `docs/handoff-per-project-storage.md` 5장의 항목(`hippo.lock` 권한, 병합 실패 재실행 테스트, OPEN-1·2·3·6)은 이번 세션에서 확인하지 않았습니다.

## 6. 변하지 않는 규약

- **작업 순서**: 규모가 중간 이상이면 인터뷰 → SRS(IEEE 29148) 수정 → 실패하는 테스트 → 구현 → 전체 테스트 통과 순서로 합니다. SRS와 코드가 다르면 SRS부터 고칩니다.
- **검증**: `cargo test --no-fail-fast`(전체), `cargo clippy --all-targets`(경고 0), `cargo fmt --check`. 동작을 바꾸면 실제 설치 환경에서도 확인합니다(4장의 측정 방법).
- **심볼 탐색과 수정**: LSP → Serena → grep 순서입니다. Serena를 쓰기 전에 `initial_instructions`와 `activate_project`(`session_db`)를 호출합니다.
- **커밋**은 사용자 확인 후에만 합니다. 커밋 메시지에 AI 서명(`Co-Authored-By` 등)을 넣지 않습니다. 이 저장소의 git 작성자는 저장소 로컬 설정에 있습니다.
- **push**: `git push origin main`. 사용자 확인 후에만 합니다.
- **개인정보 금지**: 저장소는 GitHub에 있습니다. 로컬 사용자 경로, 회사 정보, 회사 이메일을 파일과 커밋에 넣지 않습니다. 커밋 전에 `git grep`으로 확인합니다.
- **`~/.claude` 설정 파일**은 사용자가 요청할 때 `hippo install`/`uninstall`로만 바꿉니다.
- **문서**: 한국어 문서는 자연스러운 한국어로 씁니다. 영어 README와 한국어 README를 함께 고칩니다.

## 7. 아직 유효한 사용자 결정

- 기억 단위는 agentic loop 반복 하나입니다. `thinking`은 저장하지 않습니다. tool_result 원문은 결과 저장소에 따로 두고 SHA-256으로 중복을 없앱니다.
- 자동 주입은 2장의 결정 1~6을 따릅니다(턴 단위, 자르지 않음, 시간순, 노이즈 제외, 겹침 청크와 우선순위, 콜드 예산).
- 검색은 자동 주입과 CLI로 합니다. MCP는 쓰지 않습니다(사내 규정상 승인 필요).
- 구현 언어는 Rust입니다. 임베딩 모델과 벡터 DB는 언제든 바꿀 수 있어야 합니다.
- 임계값 같은 수치는 확정하지 않고 설정값으로 둡니다.
- 데몬과 Ollama는 필요할 때 자동으로 띄웁니다. 데몬은 유휴 시간이 지나면 스스로 내려가고, Ollama는 hippo가 끄지 않습니다.
- 저장은 프로젝트별로 합니다. 과거 기록은 `hippo import`로만 가져옵니다.
- CLI 기본 언어는 영어이고, `[ui] language = "ko"`로 바꿀 수 있습니다. 이 설정은 GUI에서도 바꿀 수 있어야 합니다.
- 현재는 macOS만 지원합니다.
- 다음 과제 순서: GUI → Laya 재순위.
