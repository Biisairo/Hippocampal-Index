## 2. 지난 세션에서 한 일 (끝남, 참고용)

GUI 과제를 끝냈습니다. 커밋은 `8a18206`(SRS 0.12), `b3d7dd7`(MIT 라이선스), `a17a411`(기능)입니다.

| 기능 | 내용 |
|------|------|
| `hippo gui` | egui/eframe 네이티브 창. 탭은 상태, 설정, 가져오기, 검색, 프로젝트, Claude 적용, 정보의 7개입니다(FR-GUI-1~12) |
| `hippo import --dry-run` | 목록 DB를 바꾸지 않는 미리 보기(FR-IMP-9). `import_prepare`의 `dry_run` 필드 |
| 후보 정보 | 시작 시각, 시작 경로, 크기, 첫 프롬프트(마스킹 후 80자), 가져오기 상태(`새 세션`/`실시간만`/`가져옴`/`다른 프로젝트`) (FR-IMP-8) |
| 데몬 `shutdown` 요청 | 유휴 종료와 같은 경로로 끝납니다. 재색인 중에는 거부합니다(FR-DMN-11) |
| 설정 부분 저장 | `src/config_edit.rs`. `toml_edit`로 바꾼 키만 고치고, 기본값과 같으면 키를 지웁니다. 재시작·재색인이 필요한지 판정합니다 |
| 공용 동작 | `src/commands.rs`. CLI와 GUI가 함께 씁니다. 설치, 가져오기 결과 줄, 데몬 요청(`query`), 경로·범위 해석 |

### 지난 세션에서 사용자가 정한 것
1. GUI는 네이티브(egui/eframe)로 만듭니다. "웹 UI" 비목표는 유지합니다. 웹뷰와 GUI용 HTTP 서버는 쓰지 않습니다.
2. GUI는 `hippo` 바이너리에 항상 포함합니다. 근거: 시작 시간이 약 1ms만 늘어납니다.
3. 설정은 바꾼 키만 저장합니다. 데몬 반영은 `shutdown` 요청과 "데몬 다시 시작" 버튼으로 합니다.
4. import 미리 보기와 세션 선택을 넣고, CLI에도 `--dry-run`을 둡니다.
5. 진행 표시는 2초 폴링으로 합니다. **폴링도 데몬을 띄웁니다.** GUI가 열려 있는 동안 데몬은 유휴 종료하지 않습니다.
6. 라이선스는 MIT입니다. 의존 crate는 모두 허용형이고, Apache-2.0 전용(LanceDB, Arrow, DataFusion, winit)도 MIT와 호환됩니다. 바이너리를 배포하게 되면 제3자 고지를 넣어야 합니다(아직 배포하지 않음).

## 3. Laya 재순위 과제

### 배경
자동 주입은 벡터 유사도 임계값(0.40)을 넘은 반복을 RRF 순서로 보고, 턴 단위로 최대 3개를 넣습니다(FR-RET-3, FR-RET-4). 사용자가 다음 과제로 Laya 재순위를 정했습니다. 순서는 "GUI → Laya"였습니다. 사용자가 준 자료는 `https://github.com/NandhaKishorM/laya`입니다.

### 조사한 사실 (11/03, 저장소 기준. 독립 검증 없음)
- **모델 성격**: 비자기회귀 판단 모델입니다. choice/score/noul 질문에 확률을 돌려줍니다. TypeSafe Jev와 같은 `POST /v1/systemone` 프로토콜을 씁니다.
- **체크포인트**: `laya`(421M, 영어)와 `laya-multilingual`(322M, 100개 이상 언어)입니다.
  - 한국어 정확도(MASSIVE intent, 저자 측정): laya 0.110, multilingual 0.470
  - RAG 관련성 판단: laya 0.625, multilingual 0.657
- **실행 환경**: Python 3.10+, PyTorch, transformers가 필요합니다. `pip install "laya[serve]"`로 `laya-serve`를 띄웁니다(기본 `0.0.0.0:8000`). GGUF/Ollama 배포는 없고, ONNX(`laya[onnx]`)는 있습니다. 라이선스는 Apache-2.0입니다.
- **지연(저자 측정)**: M1 Pro 1행 58ms, M5 Pro 8행 136ms, CPU 4코어 1질문 193~580ms.
- **보안 주의**: 기본 바인딩이 `0.0.0.0`이고, `LAYA_API_KEY`가 없으면 인증이 없습니다. 쓴다면 `127.0.0.1`로 묶어야 합니다. 그래야 C-4(로컬 통신만 허용)와 맞습니다.

### 결정할 것 (사용자와 하나씩, 의존 순서)
1. **정보보호팀 승인**
   - 로컬 모델이라도 새 AI 도구에 해당하므로, 사내 규정상 정보보호팀 승인 대상인지 사용자에게 확인합니다.
   - 승인 전에는 Laya를 설치하거나 실행하지 않습니다. 승인 여부는 사용자가 판단할 일이며, 대신 판단하지 않습니다.
2. **평가셋**: 재순위가 필요한지 판단하려면 지금 방식의 정답 포함률부터 재야 합니다.
   - 과거 질문과 정답 턴을 짝지은 평가셋 10~20개를 만듭니다.
   - 정할 것: 어디서 질문을 뽑을지(실제 과거 프롬프트), 정답 턴을 누가 정할지(사용자 확인), 저장 위치(저장소에 넣으면 개인정보 규약에 걸리므로 저장소 밖을 권함).
3. **측정 기준**
   - 지금 턴 단위 주입의 recall@3을 잽니다.
   - 임계값(OPEN-5)을 바꾸면서 함께 봅니다. 메타 질문("방금 주입됐어?")에도 관련 없는 기억이 들어오는 문제가 있습니다.
   - 이 결과로 재순위를 넣을지 정합니다. 넣지 않는 결론도 가능합니다.
4. **실행 방식**(재순위를 넣는 경우)
   - Python 서버(`laya-serve`, 127.0.0.1) 또는 ONNX 중에서 고릅니다.
   - 데몬이 띄울지, 사용자가 띄울지 정합니다. 기존 원칙은 "필요할 때 자동으로 띄운다"입니다.
   - 체크포인트는 한국어 때문에 multilingual을 권합니다.
5. **주입 예산**
   - 재순위 요청이 임베딩과 같은 장비를 쓰면 지난번처럼 예산 초과 문제가 다시 생길 수 있습니다.
   - 정할 것: 재순위 후보 수, 시간 예산, 실패하거나 시간을 넘었을 때의 대체 동작(재순위 없이 기존 순서).
6. **교체 가능성**
   - 임베더와 벡터 저장소처럼 재순위기도 트레이트로 두고 설정으로 끌 수 있게 할지 정합니다.
   - 기존 원칙은 "모델·DB는 언제든 바꿀 수 있어야 한다"입니다.

## 4. 값을 치르고 배운 것 (지난 세션)

### 설치와 데몬
- **이전 데몬과 새 클라이언트를 섞지 않습니다.** 새 필드는 `#[serde(default)]`라 이전 데몬이 모르는 필드를 **조용히 무시**합니다. 예를 들어 `dry_run: true`를 이전 데몬에 보내면 실제 가져오기 준비가 실행되어 목록 DB가 바뀝니다. 프로토콜을 바꾼 뒤 실제 데이터로 시험할 때는 다시 설치하고 데몬을 다시 띄운 뒤에 합니다.
- **재설치 순서**: 한 명령 안에서 순서대로 실행합니다. 데몬을 먼저 내리면 다음 도구 호출 뒤의 `PostToolBatch` hook이 **이전 바이너리**로 데몬을 바로 다시 띄웁니다.
  1. `target/release/hippo install --scope project`(실행 파일을 원자적으로 교체)
  2. 데몬 종료
  3. `~/.hippo/bin/hippo status`(새 바이너리로 데몬 시작)
- **설치 전 상태로 되돌리기**
  - 순서: `hippo uninstall --scope project` → 데몬과 hippo가 띄운 Ollama 종료 → `~/.hippo`와 `.claude/`의 백업 삭제.
  - hippo가 띄운 Ollama인지는 `lsof -p <pid>`로 `~/.hippo/logs/ollama.log`를 여는지 보고 확인합니다.
  - `rm -rf ~/.hippo`는 자동 권한 검사가 막습니다. 사용자에게 `! <명령>`으로 직접 실행해 달라고 합니다.
- 다시 설치한 뒤 실제 데이터로 측정하려면 `hippo import`(필요하면 `--wait`)로 과거 기록을 다시 가져와야 합니다. 지난번 이 프로젝트는 반복 약 1,300개, 벡터 약 5,400개였습니다.

### GUI (egui/eframe 0.37)
- 0.37은 이전 버전과 API가 많이 다릅니다.
  - `App::ui(&mut self, ui, frame)`이 필수입니다.
  - 패널은 `egui::Panel::top(id).show(ui, …)`, 확인 창은 `egui::Modal`, id는 `Id::unique`를 씁니다(`Id::new`는 deprecated).
  - 표는 `egui_extras::TableBuilder`를 씁니다.
- Grid 안의 `TextEdit`는 `desired_width`를 줘도 줄어듭니다. `ui.add_sized([w, h], …)`로 크기를 고정합니다.
- `ui.columns`는 정렬 레이아웃이라 버튼이 칸 전체로 늘어납니다. 버튼은 `ui.horizontal` 안에 둡니다.
- 한글은 eframe의 기본 기능 `system_fonts`(`system_font_fallback: true`)로 표시됩니다. 따로 폰트를 등록하지 않습니다.
- 터미널에서 띄우면 `IMKCFRunLoopWakeUpReliable` 로그 한 줄이 나옵니다. macOS 입력기 로그이고 무해합니다.
- **화면 확인 방법**
  - accesskit 덕분에 접근성 API로 탭과 버튼을 누를 수 있습니다.
  - 탭: `osascript -e 'tell application "System Events" to tell process "hippo" to click checkbox "Import" of UI element 1 of group 1 of window "hippo"'`
  - 본문 버튼은 `UI element 2`에 있습니다.
  - 캡처는 창만 찍습니다. CGWindowList에서 이름이 `hippo`인 창의 번호를 찾아 `screencapture -x -o -l<번호>`로 찍습니다. 전체 화면을 찍으면 사용자의 다른 작업 화면이 담깁니다.

### 개발 중 겪은 함정
- **Python 정규식으로 여러 곳을 한 번에 치환하지 않습니다.** 비탐욕 매칭이 앞쪽의 다른 호출까지 묶어 6곳이 잘못 바뀌었습니다. 대상 파일이 git에 없는 새 파일이라 되돌릴 사본도 없었습니다. 큰 치환 전에는 `git add`로 사본을 남깁니다.
- `cargo fmt` 뒤에는 줄 배치가 바뀌므로, 미리 만든 치환 문자열이 맞지 않습니다. 치환하기 전에 현재 내용을 다시 읽습니다.
- 테스트 합계를 `grep "test result" | awk`로 셀 때, 이름이 `result_`로 시작하는 테스트 줄이 함께 잡혀 실패 수가 틀리게 나옵니다. 실패는 `grep -c "\.\.\. FAILED"`로 셉니다.
- 데몬 테스트에서 "종료 뒤 남은 작업"을 보려면 `[index] job_batch = 1`로 둡니다. 기본값 64면 첫 묶음에 작업이 모두 들어가 종료 전에 끝납니다.
- 임베딩 스레드는 정지 플래그를 묶음 사이에서만 봅니다. 그래서 `shutdown` 뒤에도 처리 중인 묶음 1개는 마칩니다(FR-DMN-11).

### 성능 (이 장비)
- egui를 넣은 뒤 release 바이너리는 244MB에서 257MB로 커졌습니다. 프로세스 시작 시간은 p50 9.4ms로 변화가 없습니다. hook 예산에는 영향이 없습니다.
- `docs/handoff-gui.md` 4장의 임베딩 실측은 그대로 유효합니다.
  - 청크 하나: 500자 0.07s, 2,000자 0.23s, 8,000자 1.15s.
  - Ollama는 단일 슬롯입니다.
  - 모델을 다시 올리는 데 약 0.75s 걸립니다.
  - 재순위 지연을 판단할 때 이 수치를 씁니다.

## 5. 아직 고치지 않은 것

- **OPEN-5 임계값**: 0.40은 임시값입니다. 평가셋으로 함께 조정합니다(3장 결정 3번).
- **재색인 중의 주입 우선순위**: 재색인은 별도 스레드라 주입 게이트를 따르지 않습니다. 재색인 중에는 주입이 청크 하나(약 0.1초)를 기다릴 수 있습니다.
- **IF-SK-2의 문구**: "`ingest`와 `shutdown`을 뺀 요청은 `cwd`를 담는다"라고 적혀 있지만, 실제로 `status`와 `project_list`에는 `cwd`가 없습니다. 이전부터 있던 불일치이며 고치지 않았습니다.

## 6. 변하지 않는 규약

- **작업 순서**: 규모가 중간 이상이면 인터뷰 → SRS(IEEE 29148) 수정 → 실패하는 테스트 → 구현 → 전체 테스트 통과 순서로 합니다. SRS와 코드가 다르면 SRS부터 고칩니다.
- **검증**: `cargo test --no-fail-fast`(전체), `cargo clippy --all-targets`(경고 0), `cargo fmt --check`. 동작을 바꾸면 실제 설치 환경에서도 확인합니다.
- **심볼 탐색과 수정**: LSP → Serena → grep 순서입니다. Serena를 쓰기 전에 `initial_instructions`와 `activate_project`(`session_db`)를 호출합니다.
- **커밋**은 사용자 확인 후에만 합니다. 커밋 메시지에 AI 서명(`Co-Authored-By` 등)을 넣지 않습니다. 이 저장소의 git 작성자는 저장소 로컬 설정에 있습니다.
- **push**: `git push origin main`. 사용자 확인 후에만 합니다.
- **개인정보 금지**: 저장소는 GitHub에 있습니다. 로컬 사용자 경로, 회사 정보, 회사 이메일을 파일과 커밋에 넣지 않습니다. 커밋 전에 `git diff --cached`로 확인합니다. 평가셋처럼 실제 대화가 담긴 자료는 저장소에 넣지 않습니다.
- **새 AI 도구**: 로컬 모델이라도 새 AI 도구와 MCP 서버는 정보보호팀 승인 대상입니다. 승인 여부는 사용자가 판단합니다.
- **`~/.claude` 설정 파일**은 사용자가 요청할 때 `hippo install`/`uninstall`로만 바꿉니다.
- **문서**: 한국어 문서는 자연스러운 한국어로 씁니다. 영어 README와 한국어 README를 함께 고칩니다.

## 7. 아직 유효한 사용자 결정

- 기억 단위는 agentic loop 반복 하나입니다. `thinking`은 저장하지 않습니다. tool_result 원문은 결과 저장소에 따로 두고 SHA-256으로 중복을 없앱니다.
- 자동 주입은 다음 원칙을 따릅니다.
  - 단위는 턴이고, 자르지 않습니다.
  - 블록은 시간순으로 놓습니다.
  - API 오류 안내문과 `<task-notification>` 프롬프트는 노이즈로 보고 뺍니다.
  - 청크는 1,000자이고 200자가 겹칩니다. 실시간 작업이 가져오기 작업보다 먼저입니다.
  - 데몬이나 모델이 콜드이면 콜드 예산(2,500ms)을 씁니다.
- 검색은 자동 주입과 CLI(그리고 GUI)로 합니다. MCP는 쓰지 않습니다(사내 규정상 승인 필요).
- 구현 언어는 Rust입니다. 임베딩 모델과 벡터 DB는 언제든 바꿀 수 있어야 합니다.
- 임계값 같은 수치는 확정하지 않고 설정값으로 둡니다.
- 데몬과 Ollama는 필요할 때 자동으로 띄웁니다. 데몬은 유휴 시간이 지나면 스스로 내려가고, Ollama는 hippo가 끄지 않습니다.
- 저장은 프로젝트별로 합니다. 과거 기록은 `hippo import`로만 가져옵니다.
- CLI 기본 언어는 영어이고, `[ui] language = "ko"`로 바꿀 수 있습니다. GUI도 이 설정을 따릅니다.
- 설치는 현재 프로젝트에만 합니다(`--scope project`).
- 현재는 macOS만 지원합니다.
- GUI 결정은 2장의 1~6입니다.
- 과제 순서: GUI(완료) → Laya 재순위.
