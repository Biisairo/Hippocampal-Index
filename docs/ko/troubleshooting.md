## 1. 증상별 확인 사항

먼저 앱의 [상태 탭](usage.md#상태-탭)(또는 `hippo status`)을 보십시오. 로그는 `~/.hippo/logs/`에 있습니다.

| 증상 | 확인할 것 |
|------|-----------|
| 앱이 열리지 않음("손상되었습니다" 등) | 내려받은 앱의 격리 속성 때문입니다. `xattr -dr com.apple.quarantine hippo.app`을 실행합니다([시작하기](getting-started.md#방법-a-릴리스에서-받기)) |
| 창 위쪽에 "설치되어 있지 않습니다" 또는 "다릅니다" 안내 | **Claude 적용** 탭에서 **미리 보기**와 **적용**을 누릅니다. 그 전까지는 정보 탭과 Claude 적용 탭만 쓸 수 있습니다 |
| 오른쪽 위 데몬 표시가 빨간색, `hippo: daemon not reachable` | 데몬을 띄우지 못했습니다. `~/.hippo/logs/daemon.err`를 확인하십시오(예: 설정 오류). `[daemon] autostart = false`이면 직접 띄워야 합니다 |
| 임베딩 큐가 줄지 않음(`embed_jobs`) | 모델을 받았는지(`ollama list`), `hippo`가 Ollama를 띄울 수 있었는지(`~/.hippo/logs/ollama.log`, `hippo.log`) 확인합니다. 작업은 5초마다 다시 시도합니다 |
| 검색 결과에 "벡터 검색을 쓰지 못해 키워드 검색 결과만 표시합니다"가 나옴 | 임베딩에 실패했습니다(Ollama를 띄우지 못했거나 모델이 없음). 복구될 때까지 키워드 검색 결과만 나옵니다 |
| 호환성이 `mismatch` | 모델이나 차원이 바뀌었습니다. 프로젝트 탭에서 **재색인**을 누릅니다(`hippo reindex`) |
| 자동 주입이 되지 않음 | 주입이 일시정지 상태인지 상태 탭에서 확인합니다. 주입은 같은 프로젝트의 다른 세션만 대상입니다. [주입 미리 보기](usage.md#이-프로젝트에-질의)로 사유를 보고, 필요하면 `[inject] threshold`를 낮춥니다 |
| 새 대화가 기록되지 않음 | 저장이 일시정지 상태인지 확인합니다. hook을 적용한 뒤 Claude Code 세션을 새로 시작했는지 확인합니다 |
| 적용할 때 `refusing to modify through a symbolic link` | 설정 파일이 심볼릭 링크입니다. 실제 파일이 있는 Claude 폴더를 고르거나, `hippo hooks-config` 출력을 직접 넣으십시오 |
| 스풀 대기(`spool_pending`)가 0보다 큼 | 데몬이 꺼져 있던 동안의 요청입니다. 데몬이 시작되면 처리됩니다 |
| `lance-*`나 `protoc`에서 빌드 실패 | `brew reinstall protobuf` 뒤 `protoc --version`을 확인합니다 |
| 0.14 이하 버전에서 올린 뒤 `vectors/`가 매우 큼(수십 GB) | 0.14 이하 버전은 LanceDB의 버전을 모두 남겼습니다. 업그레이드 뒤 첫 정리에서 지워지지만, 몇 분 걸릴 수 있고 그동안 그 프로젝트의 검색이 기다립니다. 바로 비우려면 재색인을 실행하십시오 |

## 2. 알려진 한계

- 지금은 macOS만 지원합니다.
- 자동 주입의 품질은 `inject.threshold`에 달려 있습니다. "방금 주입됐어?"처럼 과거에 같은 말을 한 적이 있는 메타 질문에는 관련 없는 기억이 들어올 수 있습니다(SRS 부록 C).
- "버그"처럼 2자인 한국어 단어는 키워드 검색으로 찾을 수 없습니다(FTS5 trigram은 3자 이상 필요). 이런 단어는 벡터 검색이 담당합니다.
- 대화형 세션에서 아직 확인하지 못한 것: 백그라운드 알림 뒤 hook 실행 여부(OPEN-1), Esc 중단(OPEN-2), compaction(OPEN-3), `Stop` 실행 시점에 마지막 줄이 기록되어 있는지(OPEN-6).
- 설치 기록은 Claude 폴더 하나만 남깁니다. 같은 데이터 루트로 여러 Claude 폴더에 설치했다면, 완전 삭제 전에 나머지 폴더는 `hippo uninstall --claude-dir <경로>`로 직접 해제해야 합니다.
- 데몬이 시그널로 종료되면 소켓 파일이 남습니다. 다음 시작 때 지워집니다.
- 아직 보존 기간 정책이 없습니다. 지우기 전까지 기억이 계속 쌓입니다([기록 지우기](usage.md#기록-지우기) 참고).
- 결과(도구 출력)의 중복 제거는 프로젝트 안에서만 합니다. 같은 출력이 두 프로젝트에 있으면 각각 저장합니다.
- git이 아닌 폴더를 옮기면 자동으로 이어지지 않습니다. 이전 경로에서 가져와야 합니다.
- 실시간 수집은 hook이 알려 준 턴부터 저장합니다. 그 앞의 기록은 가져오기로 채워야 합니다.
- 이전 경로가 사라진 과거 세션은 어느 프로젝트의 것인지 자동으로 알 수 없습니다. 가져오기의 원본에 이전 경로를 직접 넣어야 합니다.
- 단일 저장소 배치(v0.1, `~/.hippo/records.sqlite`)의 데이터는 새 배치로 옮기지 않습니다.
- 정보 탭은 README의 그림을 보여 주지 않습니다. 코드 블록의 복사 버튼 아이콘이 빈 사각형으로 보일 수 있습니다.
