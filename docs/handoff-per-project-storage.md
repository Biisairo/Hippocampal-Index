## 2. 과제 A 결과 (끝남, 참고용)

### 사용자가 정한 것
1. **프로젝트 키**: 세션 시작 경로로 정하고, 세션이 끝날 때까지 고정합니다. 세션 시작 경로는 transcript에서 `cwd`를 가진 첫 줄의 값입니다.
2. **위치**: git 저장소는 git common dir, git이 아닌 폴더는 그 폴더 경로입니다. 프로젝트마다 위치는 1개이며 경로 목록이나 라우팅은 기록하지 않습니다. **worktree는 git으로 확인해 원본 프로젝트에 저장합니다.**
3. **폴더 이동**: git 저장소는 루트 커밋이 같고 이전 위치가 없어졌으면 자동으로 잇습니다. "잇는다"는 **기존 저장소를 현재 경로로 가져온다**는 뜻입니다. 현재 경로를 이전 저장소로 보내는 라우팅이 아닙니다. 이렇게 해야 라우팅을 따로 기록하지 않아도 이후 작업이 자연스럽게 저장됩니다.
4. **같은 저장소의 독립 clone**: 원본 위치가 남아 있으면 별도 프로젝트로 봅니다. worktree만 합칩니다.
5. **배치**: 목록 DB `~/.hippo/registry.sqlite`를 두고, 저장소는 `~/.hippo/projects/<무작위 hex 32자>/`에 둡니다.
6. **`--scope all`**: 유지합니다. 프로젝트마다 검색한 뒤 RRF로 합칩니다. 자동 주입은 현재 프로젝트만 대상으로 합니다.
7. **데몬**: 스레드 구조를 유지합니다(쓰기 스레드 1개, 임베딩 스레드 1개). 저장소는 처음 필요할 때 열고, LRU로 닫습니다(`max_open_projects`, 기본 8).
8. **명령 단위**: `reindex`는 기본으로 전체, `status`는 프로젝트별 목록, `show`는 현재 프로젝트를 먼저 찾습니다.
9. **임베딩 큐**: 영속 큐는 프로젝트 DB에 둡니다(반복 저장과 같은 트랜잭션). 데몬은 메모리에 단일 FIFO 큐를 둡니다. 사용자는 처음에 "모델 앞에 큐 하나"를 원했습니다. 전역 DB 큐는 원자성이 깨져서 이 방식으로 합의했습니다.
10. **수동 조치 `hippo project adopt <id|이전 경로>`**: 이전 프로젝트의 기록을 현재 경로의 프로젝트로 가져옵니다. 현재 경로에 프로젝트가 없으면 위치만 바꿉니다. 프로젝트가 있으면 병합하고, 모델이 같으면 벡터를 복사하며 다르면 다시 임베딩합니다.
11. 기존 데이터 마이그레이션은 하지 않습니다(SRS 비목표).

### 코드 구성 (새로 생기거나 크게 바뀐 것)
- `src/project.rs`: `normalize`, `locate`(git 실행, 시간 제한 `[project] git_timeout_ms`)
- `src/registry.rs`: `Registry::resolve`(기록 포함 판정), `lookup`(조회 전용), `bind_session`, `relocate`, `absorb`, `find_source`
- `src/store.rs`: `embed_jobs.enqueued_at`, `pending_jobs`, `merge_from`(ATTACH 사용, FTS 행도 함께 넣음)
- `src/daemon.rs`: 다시 작성했습니다. `ProjectHandle`, `OpenProjects`(LRU), `EmbedQueue`(메모리 FIFO), `WriteJob`(수집과 adopt), `embed_lock`(병합과 임베딩이 서로 막음)
- `src/protocol.rs`: `Scope`, `ProjectStatus`, 그리고 `Request::{Search, Show, Reindex, ProjectList, ProjectAdopt}`의 새 필드
- `VectorStore::scan` 추가, `vector_source(config)`에서 `paths` 인자 제거

## 3. 과제 B: 과거 기록 import 재검토

### 지금 동작 (실측으로 확인함)
- 세션마다 "어디까지 읽었는지(안전 offset)"를 원본 저장소의 `sessions` 테이블에 저장합니다(FR-EXT-1). 과제 A 이후로는 세션이 고정된 **프로젝트 저장소**에 저장합니다.
- **처음 보는 세션은 offset이 0입니다.** 그래서 설치 후 hook이 처음 실행된 세션은 **transcript를 처음부터** 읽습니다. 설치 전에 오간 대화도 함께 들어갑니다.
- 전역 설치 직후, 이미 열려 있던 세션 3개가 모두 처음부터 수집되었습니다(반복 566개, 임베딩 작업 약 1,000개).
- **닫힌 과거 세션의 로그**(`~/.claude/projects/*/*.jsonl`, 당시 317개)는 읽지 않습니다. hook이 실행되지 않기 때문입니다.

### 과제 A와 연결되는 점
- 세션 → 프로젝트는 transcript 첫 `cwd` 줄로 정합니다(FR-PRJ-1). import도 같은 함수(`ingest::session_start_cwd`)와 같은 판정(`Registry::resolve`)을 쓰면 됩니다.
- 과거 세션의 경로는 지금 없을 수 있습니다. 경로가 없으면 git 정보를 얻지 못하므로 git이 아닌 폴더(`dir`)로 판정되고, 그 경로 문자열이 위치가 됩니다. 이렇게 되면 이후 같은 저장소의 git 프로젝트와 따로 나뉩니다. import에서 이 경우를 어떻게 다룰지 정해야 합니다.
- 수집은 쓰기 스레드 하나가 순서대로 처리합니다(FR-DMN-6). 대량 import가 이 스레드를 오래 잡으면 실시간 수집 hook이 기다립니다. hook 클라이언트의 대기 시간은 10초이고, 넘으면 스풀에 씁니다.
- 임베딩은 메모리 단일 FIFO 큐로 처리합니다. 대량 import는 큐 앞을 오래 차지해 실시간 기록의 임베딩을 늦춥니다. 우선순위를 둘지 정해야 합니다.

### B. 결정할 것 (사용자와 하나씩)
1. **과거 세션을 다시 열었을 때**(`claude --resume`, `--continue`): 이전 턴들을 처음부터 수집할지, 다시 연 시점 이후만 수집할지 정합니다.
   - 먼저 확인할 사실: 재개할 때 Claude Code가 같은 transcript 파일에 이어 쓰는지, 새 session id로 새 파일을 만들고 이전 기록을 복사하는지 확인합니다. 복사한다면 같은 반복이 다른 session id로 두 번 저장됩니다. 반복 id가 `<session_id>:<message_id>`이므로 중복이 제거되지 않습니다.
   - 확인 방법: 이전 세션에서 쓴 `claude -p --settings <격리 설정>` 방식(`probe/`)으로 hook 입력과 transcript를 기록합니다. `~/.claude` 설정은 건드리지 않습니다.
2. **닫힌 과거 세션 일괄 가져오기**(`hippo import` 같은 명령): 만들지 말지, 만든다면 범위를 어떻게 할지 정합니다.
   - 범위 후보: 전체, 프로젝트 단위(과제 A의 위치와 연결), 특정 날짜 이후.
   - 비용: 0.6b 모델의 임베딩 처리량은 실측 초당 약 2~3개였습니다. 세션이 수백 개면 시간이 오래 걸리므로, 진행률 표시와 중단 후 재개가 필요합니다.
   - 서브에이전트 transcript(`<session>/subagents/agent-*.jsonl`)는 지금 정책상 저장하지 않습니다(서브에이전트 보고만 결과로 저장). import에서도 같은 정책을 따를지 정합니다.
3. **설치 직후 이미 열려 있는 세션**: 지금처럼 처음부터 읽을지, 설치 시점 이후만 읽을지 정합니다. 1번과 같은 결정일 수 있습니다.

## 4. 값을 치르고 배운 것

### Claude Code hook과 transcript (2.1.316 실측, SRS 부록 A)
- `Stop`은 턴 단위, `PostToolBatch`는 반복 단위로 실행됩니다(병렬 호출 batch가 끝난 뒤 한 번). `TaskCompleted`는 작업 목록 항목용이라 쓸 수 없습니다.
- 서브에이전트 내부 hook 입력에는 `agent_id`가 있습니다. 메인 루프와 이것으로 구분합니다.
- 병렬 호출의 `tool_use`와 `tool_result`는 transcript에 교차로 기록됩니다. 결과가 모두 모였다고 반복이 끝난 것은 아닙니다.
- assistant 줄에는 `promptId`가 없습니다. 직전 user 줄에서 가져옵니다.
- 백그라운드 서브에이전트 보고(`<agent-message>`)는 `isMeta: true`입니다. `<task-notification>`은 그렇지 않습니다.
- 백그라운드 shell 완료에는 hook이 없습니다. 완료 알림은 transcript에 user 메시지로 들어오고, 새 `promptId`로 루프가 돕니다.
- 포그라운드 Agent의 tool_result 본문은 안내 문구입니다. 보고는 `toolUseResult.handbackReport.text`에 있습니다(이 환경 기준).
- **전역 설치는 이미 열려 있는 세션에도 바로 적용됩니다**(설정을 다시 읽음).
- `~/.claude/projects/<slug>`의 slug는 경로의 영숫자 외 문자를 모두 `-`로 바꾼 값입니다(`session_db` → `session-db`). 원래 경로로 되돌릴 수 없습니다. 하위 디렉터리에서 연 세션은 별도 slug가 됩니다(예: `…-session-db-probe`).

### 개발 중 겪은 함정
- Serena `rename_symbol`은 `src` 안의 참조만 바꾸고 통합 테스트(`tests/`)의 참조는 놓칩니다. 이름을 바꾼 뒤 `grep`으로 남은 곳을 확인합니다.
- rustfmt가 줄바꿈을 바꾼 뒤에는 예전 문자열로 찾아 바꾸는 스크립트가 실패합니다. 실제 파일 내용을 먼저 읽습니다.
- `cargo fmt`가 파일을 바꾸면 Write 도구가 "읽은 뒤 바뀜"으로 거부합니다. 다시 Read한 뒤 씁니다.
- 한국어가 든 Python을 bash heredoc으로 넘기면 "Non-UTF-8 code" 오류가 날 때가 있습니다. 스크립트를 `/tmp` 파일로 쓰고 `python3 -X utf8 <파일>`로 실행합니다.
- zsh는 변수 안의 glob을 펼치지 않습니다(`FILES="src/*.rs"; cmd $FILES` 실패).
- 실제 바이너리로 데몬을 띄우는 CLI 테스트는 프로세스를 남길 수 있습니다. 테스트 설정에 `[daemon] autostart = false`나 짧은 `idle_timeout_secs`를 넣습니다. 테스트 후 `pgrep -fl "hippo --root"`로 확인합니다.
- LanceDB 때문에 release 첫 빌드는 약 4분 걸립니다. `protoc`가 필요합니다.
- FTS는 trigram이라 3자 미만 토큰은 검색되지 않습니다("원본 결과"는 0건). 테스트 데이터에는 3자 이상 토큰을 씁니다.
- 결과 원문은 해시로 중복을 제거합니다. 같은 fixture로 두 프로젝트를 만들어 병합하면 결과 벡터가 합쳐집니다(반복 4 + 결과 2 = 6).
- `memory` 벡터 백엔드는 다시 열면 비어 있습니다. 그래서 재색인이 끝나면 핸들을 캐시에서 빼지 않고, 새 저장소 핸들로 바꿔 넣습니다(`Shared::install`).
- macOS 임시 디렉터리는 `/var` → `/private/var`로 정규화됩니다. 테스트에서 위치를 비교할 때는 `fs::canonicalize`한 값을 씁니다.
- fixture의 `cwd`(`/Users/user/…`)는 존재하지 않는 경로라서 git이 아닌 위치로 판정되고, 그 문자열 그대로 위치가 됩니다.
- 백그라운드 보안 리뷰 플러그인이 커밋마다 지적을 냅니다. 지금까지 반영한 것: PEM 잘린 키, 치환 템플릿 주입, DB/소켓 권한, 주입 블록 이스케이프, 터미널 제어 문자(이번에 `status`·`project list` 출력에도 적용), 위조 알림으로 임의 파일 읽기(경로·작업 id·O_NOFOLLOW), 임베더 URL 우회와 리다이렉트, 설치 시 임시 파일·백업 링크 추적.
- Ollama 첫 호출은 모델 로딩으로 약 1초 걸립니다. `keep_alive`로 유지합니다.
- 자동 주입 임계값 실측(표본 4개): 관련 0.46~0.68, 무관 0.21~0.30. 기본값 0.40은 임시값입니다(OPEN-5).

### 사용자와 일하는 방법
- `AskUserQuestion` 대화창에서는 그 앞에 쓴 설명이 보이지 않습니다. 사용자가 "설명이 없잖아"라고 했습니다. 예시 상황은 질문 문장 안에 넣습니다.
- 사용자는 권장안을 그대로 받기도 하지만, 방향을 직접 바꾸기도 합니다(예: 라우팅 대신 "현재 경로로 가져오기"). 답의 문장을 그대로 읽고, 해석이 둘이면 확인합니다.

## 5. 아직 고치지 않은 것

- **엔진의 `cwd` 필터를 쓰지 않습니다.** 과제 A 이후 데몬은 `SearchRequest.cwd`, `FtsFilter.cwd`, `VectorFilter.cwd`에 항상 `None`을 넘깁니다. 지우면 SRS FR-SWP-2(필터 정의)와 계약 테스트(`tests/common/contract.rs`), Lance 필터식도 바뀝니다. 지울지 사용자에게 묻습니다.
- **`~/.hippo/hippo.lock`이 0644로 만들어집니다.** 0600으로 맞춥니다(`daemon.rs`의 `start`에서 잠금 파일을 여는 부분).
- **병합이 중간에 실패한 뒤 다시 실행하는 경우를 데몬 수준에서 테스트하지 않았습니다.** `RecordStore::merge_from`의 반복 실행과 `Registry::absorb`는 단위 테스트로 확인했습니다. 데몬 `merge`의 단계 (1)~(4) 사이 실패는 재현하지 못했습니다.
- IF-SKL-1(skill 문서)은 구현하지 않았습니다. README 4.5에 `CLAUDE.md` 안내로 대신했습니다. 사용자 결정이 필요합니다.
- OPEN-1, 2, 3, 6은 대화형 세션에서 아직 확인하지 못했습니다. 그중 OPEN-6(Stop 시점에 마지막 줄이 기록되어 있는가)의 영향이 가장 큽니다.

## 7. 아직 유효한 사용자 결정

- 기억 단위는 agentic loop 반복 하나(입력 + 도구 호출 + 응답)입니다. `thinking`은 저장하지 않습니다. tool_result는 원문을 저장하되 결과 저장소에 따로 두고, SHA-256으로 중복을 없앱니다.
- 백그라운드 작업(서브에이전트, shell)은 시작 호출과 완료 결과를 한 쌍으로 연결합니다. 서브에이전트 내부 반복은 저장하지 않습니다.
- 검색은 자동 주입과 CLI로 합니다. MCP는 쓰지 않습니다(사내 규정상 승인 필요).
- 구현 언어는 Rust입니다. 임베딩 모델과 벡터 DB는 언제든 바꿀 수 있어야 합니다(원본은 SQLite, 벡터 저장소는 파생 인덱스).
- 임계값 같은 수치는 확정하지 않고 설정값으로 둡니다.
- 데몬과 Ollama는 필요할 때 자동으로 띄웁니다. 데몬은 유휴 시간이 지나면 스스로 내려가고, Ollama는 hippo가 끄지 않습니다.
- 바이너리는 옮기지 않고 빌드 위치에서 설치해도 됩니다.
- 프로젝트 풀 네임은 Hippocampal Index이고, 명령어와 줄인 이름은 `hippo`입니다.
- 저장은 프로젝트별로 합니다. 결정 내용은 2장을 따릅니다.
